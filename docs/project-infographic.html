When things go wrong

Four branches, one non-negotiable rule

A downstream timeout has an unknown outcome, not a failed one — a read timeout can't be told apart from a call that never arrived. Compensating blindly risks inventing money. Every path below reconciles against Account before it moves anything back.

FAILED
Fraud blocks the source account
Screened before the debit — nothing has moved. The transfer fails clean, nothing to compensate.
COMPENSATED
Fraud blocks the destination account
The source is already debited. CompensationScheduler credits it back automatically via idempotent replay.
COMPENSATION_FAILED
The credit-back itself fails
Routed to manual review, not auto-retried — the one saga edge case deliberately left for a human.
503 · CIRCUIT OPEN
Account or Fraud is down
Breaker opens after retries exhaust. Fails fast, no hang, no dangling partial state.

Every debit/credit carries a required Idempotency-Key, backed by the AccountOperation ledger — so an automatic replay can never double-move money.

Tuned, not guessed

The Resilience4j numbers actually in config

accountService 30 calls 15 50% 10s 3 3× · 200ms

Retry is the outer decorator: each logical call can hit the breaker up to 3× before it succeeds or gives up. Window and minimum are scaled ×3 from the original design intent (10 / 5) — unscaled, a full outage tripped the breaker at just 2 failed logical calls, found live during verification.

Six services, one ledger

Database-per-service, no shared reads

Each stateful service owns its data exclusively — no service ever queries another's database directly.

service port responsibility state
Gateway 8080 Single entry point; routes requests, validates JWT stateless
Account 8081 Owns accounts & balances; debit/credit with optimistic locking PostgreSQL
Transfer 8082 Orchestrates the saga; owns transfer/ledger history + outbox PostgreSQL
Fraud 8084 Rule-based risk check on a transfer (blocklist screen) stateless
Notification 8083 Consumes transfer-outcome events; logs "notification sent" stateless
Keycloak (Auth) 8180 Issues/validates JWT via OAuth2/OIDC, pre-configured realm self-managed

Run it locally
docker compose up brings up all 6 services, Postgres, Kafka, Keycloak, and the observability stack (Tempo, OTel Collector, Prometheus, Grafana) in one shot.

Not a production banking system — no real payment rails, no double-entry general ledger, no multi-currency, no Kubernetes or service mesh. Scope is deliberately bounded to demonstrate synchronous resilience and asynchronous eventing credibly, in one small, concrete flow.
